# DESIGN-FLOW-CANVAS: Flow 画布的空间与按需查看

Flow 用来辨认 Agent、查看真实活动和导航到已有会话、运行记录与固定交付审查。画布不是第二套交付工作台，也不从运行事件推断用户关系。本设计延续 [ADR 0003](../adr/0003-commit-the-canvas.md)、[ADR 0006](../adr/0006-main-agent-and-subagent-roles.md)、[ADR 0008](../adr/0008-independent-run-records.md) 与 [ADR 0011](../adr/0011-flow-groups-project-existing-evidence.md)。Flow 拓扑格式不变，读取协议增加轻量活动摘要和证据导航身份。

## DESIGN-FLOW-IDENTITY: 身份、状态和选择分别表达

总览只显示长期 Agent 和用户 Link；进入编排者后，只显示该编排者、默认成员及需要查看的实际 Run 角色。长期 Agent、编排者和角色的图标主体分别采用 46、52、40px；共享角色和临时证据另有标记，不创建角色副本。名称最多两行，模型次行只在有可靠信息或明确继承规则时出现。运行、失败、待回答、未读完成有独立徽标与文字；选中轮廓、连接起点和键盘焦点不覆盖状态。

`ProviderLogo` 集中管理本地品牌资产及颜色。供应商品牌只来自已加载会话的结构化 `model.provider` 或明确配置的 `provider/model`。裸模型 ID 只有在已有目录中唯一匹配时才识别。没有目录时不为取图标额外打开会话或请求模型。

首版识别 Anthropic/Claude、OpenAI（含 openai-codex）、Google/Gemini 的已知接入别名和 DeepSeek。聚合渠道、自定义 endpoint、不明模型使用中性首字母；不从模型名字猜品牌。继承调用者的角色保留继承文字和中性标记，不用最新一次 Run 冒充唯一模型。会话模型变化时直接重新投影。

品牌色只用于图标主体与摘要。状态使用状态色；普通边使用低对比专用 token。Logo 资源来自 Lobe Icons 的独立 SVG，随源码保留 MIT 许可与来源，不安装图标 SDK，也不在运行时请求第三方资源。现有 Lucide 操作图标继续使用。视觉层级和按需查看参考 affectUI Agent Graph，组件与算法独立实现。

## DESIGN-FLOW-INSPECTION: 扫视、摘要与完整详情

| 动作 | 行为与数据来源 |
|---|---|
| hover / 键盘 focus | 临时突出一跳邻域；不改变选中项，不创建会话 |
| 总览编排者单击 / Enter / Space | 进入协作组；独立摘要按钮仍可查看编排者简介 |
| 其他节点单击 / Enter / Space | 选择节点、切换轻量摘要；多选与连接操作保留原规则 |
| 摘要 | 使用已有名称、模型、状态、Goal/Brief 和最近 Run 任务或消息预览；不读取新的一份交付正文 |
| 完整详情 | 复用原节点操作与 ChatView；此时才按需打开绑定会话、加载模型目录 |
| 运行记录 | 复用原 RunPanel 及交付审查；共享角色继续携带调用者筛选 |
| 侧栏定位 | 直接打开完整详情并定位；双击长期节点仍打开完整聊天 |

显示节点 ID、规范 Agent ID 和调用者上下文分别保存。共享角色的摘要和详情携带当前编排者；在总览从侧栏选择共享角色时，先明确进入哪个组，未分配角色仍可打开原配置。组内同角色并发聚合在一个节点，并能选择具体 Run；非默认成员、已移除角色和只读审查分析有独立标记，分析 purpose 不与普通角色任务混合。活跃或正在查看的证据保留入口，不恢复已删除配置，也不把最新 Run 模型冒充角色固定模型。

摘要以图标中心为锚点，在统一投影画布坐标后按实测卡片高度垂直居中；优先朝画布内侧展开，与图标边缘保持 18px 屏幕间距，并保留 12px 画布边界。卡片宽约 280px，不随画布缩放；标题高度不参与锚点计算。画布宽度不足 520px 或两侧不足时停靠底部并限制高度。初次停靠或容器尺寸变化时最小平移节点，后续普通平移不会被摘要拉回。摘要不缩放整图。

Esc 先退出当前工具菜单、连接状态或当前查看面板，关闭后将焦点还给入口。输入框、现有 Dialog 与菜单保留自己的键盘行为。摘要、详情与工具栏中的 Delete/Backspace 不透传为删除节点。完整详情关闭后不会再弹摘要。

## DESIGN-FLOW-SPACE: 真实分配空间，保留视口

详情和编排面板是画布的并列区域，互斥显示。桌面初值 380px；工作区宽度不足 860px 时改为上下分区，详情最多占 55% 高度。窄且工作区高度不足 480px 时显示完整详情，可由关闭按钮返回画布。沿用浏览器宽度不超过 768px 时不提供 Flow 的产品范围。

ReactFlow 始终获得实际剩余尺寸。`viewport.ts` 的 `focusViewport` 负责可读定位，`revealViewport` 负责尺寸变化后的最小平移。显式定位等待布局测量；执行期间尺寸观察不得打断定位。隐藏画布的零尺寸不参与视口计算。

恢复已有视口不猜测 `(0,0,1)` 是否表示未保存，不因节点数量、SSE、轮询或状态刷新重新 fit。总览与各组分别保留视口，返回总览恢复原位置及入口焦点；当前组和组内位置使用项目级本地视图偏好，刷新可恢复，存储不可用则降级到内存。定位所选使用约 0.85–1.1 的阅读比例；只有用户选择全图或整理后总览才允许缩小到 0.2。工具栏使用 ReactFlow 的真实缩放值。

画布工具包含缩放、全图、定位所选，以及收起的整理/撤回/缩略图菜单。缩略图默认关闭，偏好只保存在设备 localStorage。项目顶栏显示名称，完整路径保留在提示中。

## DESIGN-FLOW-LAYOUT: 显式整理和展示投影

`layout.ts` 仅接收真实节点、用户保存的通信边和 memberships，返回位置映射。按无向连通分组，用稳定 ID 排序和圆周初值做 180 次有限松弛：关联节点有吸引，所有节点相互排斥，弱中心约束防止分组发散。最后按完整矩形搜索最近空位，保证标签留白，再紧凑安放断开的分组。没有根、父子层级或固定深度列；环与横向关系参与同一二维排版。输入次序、边的方向、运行状态和临时调用边不影响输出。

整理通过原 `persist(..., commitGraph: true)` 一次提交位置，保留配置、关系和绑定。提供一次撤回，只恢复之前的位置。人工拖动会清除撤回；节点、边、成员关系或位置与整理版本不一致时，撤回不可用。普通视口与运行状态不使撤回失效。保存失败明确提示当前画布未保存，继续沿用保存队列；不宣称保存成功。

`members.ts` 只返回总览或单一组的展示投影。首次进入组复用现有二维布局；此后只给新成员或临时角色找空位，不因运行变化重排已有节点。组内拖动、整理和视口只改变本地视图偏好，不写入项目文件；组内成员边和临时节点不能通过画布删除，配置编辑仍走原入口。总览的显式拓扑编辑继续使用原保存路径。

## DESIGN-FLOW-ATTENTION: 全项目关注与固定证据

`GET /api/flow/activity` 在服务端读取全项目的活跃 Run、按编排者/角色/purpose 区分的最近 Run，以及 Reviews 最新修订的目标、决定、排除和缺口。它不加载源码正文、不扫描当前 Git、不调用模型、不新增数据库；来源 Run 做项目限定的批量读取。总量独立于列表分页，条目每页 20 条，游标绑定规范项目、组和分类。

待审按最新修订中范围内 unread 对象的 Review 数统计，需修改按对象数统计；同对象多步骤、同 Review 多历史 Run 不重复。全部 hunk 已排除的对象不计入范围，seen、skipped 和排除均不代表批准。归组只取当前 revision.sourceRunId；手工或缺失来源留在未归属区。来源仍运行的放入进行中交付，来源缺失则标执行证据不可用，不默认为已结束。解析、预算、二进制等宿主源码缺口独立提示，不以零待审暗示全部覆盖。

关注项携带确定的 Run，或 Review/Revision/Target 与最低已知版本。Run 直达原时间线，Review 直接复用原文件/功能路线阅读器；只有一个可见证据容器。读取后固定当前修订，有新版只提示，用户主动切换；无来源 Run 时解释为什么不能生成路线或定位返工会话。关闭后恢复原入口焦点，入口消失时回到组标题。

Run/Review 事件只失效相关项目，短时间内合并刷新；重连和页面重新可见时补读，旧作用域响应丢弃。失败保留旧摘要并标记未同步，删除通知使已打开的审查失效，迟到响应不能复活。两个 SQLite 库不是联合事务，observedAt 只表示组合观察时间。

## DESIGN-FLOW-GEOMETRY: 同一套几何供布局和连线使用

`geometry.ts` 统一主体大小、节点静态尺寸和图标中心；实测尺寸优先于 164×154 的保守初值。节点定位与可见区域检查使用完整矩形，包括名称、模型、状态及成员区；路由和摘要锚点使用图标中心和尺寸。CSS 消费同一静态 token，避免另外维护锚点常量。

`routes.ts` 使用图标上、下、左、右四向端口。先比较直线、两种 L 形及两种中线折线候选，在无碰撞的候选中按路径长度、转弯成本和朝向目标的程度选择。按节点/方向分组，以相邻节点的几何位置和稳定 ID 排序分槽，避免边数组顺序改变出口。端点按稳定 ID 规范化，消息方向只反转路径，不改变几何。

按用户反馈，路由只把图标矩形加 6px 留白作为障碍，不为名称、模型、状态或成员文字绕路。底部端口可直接向下连接；文字层的画布同色背景遮住经过的连线，沿用 affectUI Clean 预览的视觉处理。完整矩形仍供节点排布和节点可见区域检查使用。候选均受阻时，复用障碍边界网格上的 Manhattan A*，每次路线选择最多做一次搜索；同侧分槽后重新校验。路径支持任意多个圆角，允许边互相交叉。这是有限候选与避障搜索的组合，不保证全局最优。

路由输入只包含图标几何和关系，序列化后的稳定输入用于缓存；消息脉冲和普通状态刷新不会重新求路，纯文字高度变化也不参与路由签名。四向端口、几何分槽和标签遮线借鉴 affectUI Clean 预览的设计思路；保留 piflow 自身的多段搜索，未移植依赖中心/内外圈的参考规则。

实线表示用户关系，临时调用使用虚线并保留真实事件方向；二者只在展示层组合。选中边与邻域适度提亮；无关节点保留 45% 不透明度，无关边保留 25%，以便继续辨认。节点和边共用 `--duration-fast`（250ms）与 `--ease-in-out` 对称过渡，不加延迟、位移或模糊；减少动态效果时立即切换。脉冲继续来自已有投递和 Run 变化。宽透明交互路径保留细线的命中区域，reduced-motion 使用静态活动数量。

布局在用户明确操作时做有限计算，没有持续力导进程或新图引擎。首版面向工程规模图，不承诺最优排版或布线。人工重叠可能使端口没有可行通道，此时使用确定性回退并用标签底色保护文字；不自动移动人工节点。大量障碍的有限网格搜索成本会增加，尚未对百节点密集图给出性能承诺；只有实测出现瓶颈时再替换搜索或布局实现。

## 验证入口

几何、定位、摘要位置、确定性布局、路由、成员投影与品牌识别使用现有 `node:test`；浏览器检查重点是实际尺寸、焦点、摘要不加载会话、引用调用者筛选和状态组合。使用隔离工程及合成活动，不把这些样本当成真实模型执行事实。

动效仅消费通过 revision 检查的实时 Run 事件和建立基线后的新消息投递；首次加载、历史读取、重连补读和页面重新可见不重播。相同边和方向在 500ms 内合并，1200ms 后清除；同边不堆积队列，错误使用静态标记。隐藏、退出或连接变化会清除短暂活动；减少动态效果时仍保留静态活动数量。

自动测试覆盖全项目聚合、当前修订归属、分页作用域、手工/缺失来源、运行中采集、实时事件不回放、固定修订和删除后的迟到响应。浏览器夹具和真实模型闭环分别留证；合成活动只验证投影与交互，不作为模型执行事实。
