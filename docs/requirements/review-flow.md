# REQ-REVIEW: 在交付中沿需求审查代码

用户从 Code 交付的一个入口，沿功能步骤查看实际 diff，并回看相关 PRD、技术方案和 ADR。按文件与按功能共享同一组人工记录，执行事实继续引用原 Run。

## AC-REVIEW-SOURCE: 固定可回看的比较

Code 运行前后采集源码与文档，保留既有脏基线。旧记录未采集的历史明确未知，不用当前文件补造。工作区采样不保证原子性，也不作作者归因。超限、二进制、不可读取文件和未识别符号明确显示缺口。

## AC-REVIEW-ROUTE: 模型建议有明确来源

普通打开、读取、刷新无需模型。“按功能 · 生成路线”显式启动可取消的只读分析。模型通过结构化工具提交顺序、引用和解释，宿主验证固定身份和版本；不解析最终聊天文本。路线是阅读建议，不代表实际调用关系、测试通过或人工批准。失败保留文件审查和上一份有效路线。

## AC-REVIEW-CONTEXT: 变更与依据在一起

步骤及函数可选择，纯文档步骤也能阅读。选择引用后读取固定 PRD、方案、ADR 章节；命令引用进入原工具详情，返回保留审查定位。未归类、共享对象、非函数变更和附理由排除的变更均可达。

## AC-REVIEW-DECISION: 一份人工状态

用户标记已看、需修改或略过；意见输入按需出现。文件/功能切换、路线重排和关联修正不清除人工记录。源码或文档变化产生新修订并整体待审，旧意见可回看。汇总返工意见追加到现有会话草稿，由用户编辑和发送，不自动执行。

## AC-REVIEW-RECOVERY: 可恢复且受作用域约束

刷新、断线重连、迟到响应和服务重启不能混用项目、修订或旧正文。人工记录不接受模型覆盖。路线意图可导出和重新定位导入，不携带人工已看状态或执行事实；用户可删除本机审查与源码副本，原 Run 执行记录保留。

技术方案见 [Review Flow](../design/review-flow.md)，核心取舍见 [ADR 0010](../adr/0010-fixed-review-revisions.md)。
