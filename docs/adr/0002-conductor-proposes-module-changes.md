# The Conductor proposes module changes

The Conductor is a separate role from a Module. It reads the repository and drafts a module graph: names, briefs, and links. The canvas applies that draft only after the user accepts it, so links stay user-owned. The first operation is dividing a repository into modules. Card layout, deletions, session bindings, and messages between modules wait.

A later divide keeps existing module ids, names, and briefs that already have text. It may fill an empty brief, add modules, and add links. It does not remove modules or links. The user accepts the whole Draft at once. Until then it stays in the Conductor session, and a newer reply replaces it. Each project has one Conductor session. That session can be resumed and is not a canvas module. A session card that was only placed on the canvas automatically is not a Module; the first accepted divide takes that card off the canvas and leaves the session in the list. The open panel overlays the canvas and does not move cards. Only the pinned Draft is written; prose in the conversation is not. A Draft can be accepted when every module has a name and a brief. Links may be empty. Accept stays unavailable while the next Draft is still being written. Opening the Conductor from the session list opens this panel. Accepting has no undo in this version, because a divide does not remove modules.

Considered letting the Conductor write the graph itself. That would break the rule that agents do not create or remove links on their own. Also considered making the Conductor a Module in the graph. A Module is a slice of the project; the Conductor arranges those slices and does not own one.
