# 独立的 Subagent 运行记录

采用独立的 SubagentRuns Module，统一拥有子进程执行、取消、持久化、工具步骤和重启中断恢复。Flow 仅负责用户配置的节点、成员关系和通信边，不再保存运行历史。此决策替换 ADR 0006 中运行数据嵌入 Flow 的实现。

## 数据与读取

使用 Node 内置 SQLite（Node >= 22.13），将运行摘要、输出尾部及工具步骤存入本地数据目录的 `runs.sqlite`。摘要、工具步骤、输出游标和 revision 在同一事务中提交；SSE 只在提交后广播摘要及变化的工具摘要。已有 Flow 文件内的运行记录在启动时幂等导入，提交后再移除旧字段；旧记录没有工具历史时明确标记不可用。

运行有独立身份，同一角色的并发调用不合并。调用时保存角色、模型、工具、提示及父调用身份的不可变快照。工具以 `(runId, toolCallId)` 配对，按首次观察排序，失败步骤在运行成功后仍然保留。重复和缺失事件记录诊断，不制造精确时序。

HTTP 按项目及角色/主 Agent 筛选，采用游标分页。列表提供全部仍在运行的记录与各角色最近摘要，防止活跃记录或角色状态落到分页之外。工具输入、输出仅在展开时读取；文本预览最多 8 KiB。运行输出保留最近 160000 个 UTF-16 码元，避免拆开字符对，并明确显示截断。增量读取包含版本和偏移，文本修正或游标不再可用时返回重置。浏览器按 revision 合并 SSE 与 HTTP，输出读取串行执行，重连后刷新已加载页面及此前运行中的记录。

## 时间和故障语义

只有实际观察到子进程关闭才保存确认结束时间。正常关闭会等待取消；重启时遗留的 running 记录转为 interrupted，保留最后观察时间，并单独记录发现中断的时间，不推测真实完成时刻。耗时使用单调计时。

执行失败、运行记录保存失败、证据预览失败及客户端断线分别处理。保存失败中止继续执行并单独报告；已知执行成功不会因为最终保存失败改写成执行失败。预览格式化失败不影响执行。客户端断线不取消任务。

同一数据目录只允许一个 SubagentRuns 实例，通过独立 SQLite 连接持有 OS 文件锁；进程退出或崩溃时自动释放，无需维护 PID 锁文件。所有读取和取消沿用原有认证及同源检查。服务关闭前主动结束 SSE，客户端在重连前刷新认证，兼容本地服务重启时的 Cookie 轮换。

## 产品入口与限制

Flow 工具栏和节点面板共用“运行记录”入口，提供共享时间轴、工具步骤、配置快照、输出、取消及父工具调用定位。断线或同步失败时明确标记状态可能过期；中断时间线结束于最后观察时刻。

独立上下文不等于文件系统隔离，不提供重启续跑或宿主进程硬崩溃后的外部进程托管。只记录执行阶段，不持久化模型思维文本。历史记录保留到用户自行清理数据目录，自动归档和清理策略另行设计。
