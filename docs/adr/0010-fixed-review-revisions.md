# 审查路线绑定固定修订，模型建议与人工记录分开保存

需求驱动的代码审查需要在返工、刷新和模型重排后仍能回看当时依据。我们在 Code 运行前后固定源码及文档，由宿主产生真实 diff 和对象身份，再让独立只读分析 Run 通过两个固定工具引用这些身份提交路线；不从最终聊天解析图，也不以当前文件补造历史。代价是本地源码存储和一次显式分析调用，收益是可校验引用、可复现阅读范围和明确缺失语义。

Reviews 使用独立持久化生命周期保存跨 Run 的修订、建议与用户记录，命令和交付声明继续归 SubagentRuns，按身份引用。人工决定绑定修订中的对象，共享对象不重复审批；源码或文档变更重新待审，路线调整不清除人工记录。路线既不证明运行调用关系，也不判定测试或合并通过，工作区采样仍不作作者归因。前端在现有交付详情组合这些信息，避免新增并行审查入口和执行账本。
