# 编排者作为主 Agent，下属采用可复用 Subagent 角色

画布采用混合模型：编排者是持有长期会话的主 Agent，下属默认是可复用的 Subagent 角色定义，每次委派创建独立上下文的运行实例。需要持续上下文的协作对象仍可显式创建为长期 Agent，通过用户创建的通信边协作；长期 Agent 不作为首版 subagent 委派目标。

执行集成采用当前 pi-coding-agent 1.2.0 随包提供的官方 subagent 扩展示例作为起点，复用其子进程、JSON 事件流与工具结果回传方式。相比将每个下属绑定唯一会话，这个选择允许同一角色被多个主 Agent 并发调用，并避免任务历史相互污染。共享的是角色定义，各次调用的上下文、结果和状态独立；独立上下文不提供文件系统隔离。

piflow 负责角色与运行身份、配置快照、可观察运行记录、取消和重启中断状态。示例的 `--no-session` 不提供持久会话或重启续跑保证。编排者不得被其他编排者委派，运行事件不得创建或修改用户配置的节点、成员关系及通信边。

此决策替换概要设计中“所有下属都绑定长期会话”的假设。现有 A2A 的异步投递/回复机制继续用于长期 Agent 通信；subagent 工具调用等待结果，独立于通信 Edge。
